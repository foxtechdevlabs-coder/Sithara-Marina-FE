# Folder structure

```
Sithara-Marina-FE/
├── src/
│   ├── app/                      Next.js routes, layouts, boundaries (see architecture.md)
│   │   ├── (user)/               customer website — (site), (checkout), (auth) groups
│   │   └── admin/                staff dashboard — (auth), (console) groups
│   ├── features/
│   │   ├── user/<feature>/       customer-only UI, hooks, types, helpers
│   │   └── admin/<feature>/      admin-only UI, hooks, types, helpers
│   ├── components/
│   │   ├── ui/                   generic primitives usable anywhere (Spinner, …)
│   │   ├── shared/               generic composites used by both areas (RoutePlaceholder)
│   │   ├── user/                 customer chrome (SiteHeader, SiteFooter)
│   │   └── admin/                admin chrome (DashboardShell, SidebarNav)
│   ├── services/
│   │   ├── http/                 the HTTP client, ApiError, URL builder, request types
│   │   ├── user/                 (add) customer API service modules
│   │   └── admin/                (add) admin API service modules
│   ├── config/                   env.ts (validated env), user-/admin-navigation.ts
│   ├── constants/                brand.ts, routes.ts (typed URL builders)
│   ├── lib/                      small general-purpose helpers (cx)
│   └── validation/               Zod schemas shared across features (emailSchema)
├── tests/
│   ├── unit/                     Vitest — pure functions, schemas, config
│   ├── integration/              Vitest — HTTP client against a stubbed fetch
│   └── e2e/                      Playwright — routes, layouts, headers in a real browser
├── docs/
├── AGENTS.md                     generated by `next dev` for AI coding tools (keep committed)
├── next.config.ts  tsconfig.json  eslint.config.mjs  postcss.config.mjs
├── vitest.config.ts  playwright.config.ts
├── package.json  package-lock.json
└── .env.example  .nvmrc  .editorconfig  .gitattributes  .gitignore  .prettierrc.json  .prettierignore
```

Folders marked "(add)" do not exist yet; create them with the first real file. There are no
`hooks/` or `types/` folders yet for the same reason — add `src/hooks/` or `src/types/` when a hook
or type is genuinely used by several features. There is no `public/` folder; add one for static
assets (favicons, images) when needed.

## Where does my code go?

| You are writing…                            | Put it in                                              |
| ------------------------------------------- | ------------------------------------------------------ |
| A customer page                             | `src/app/(user)/(site                                  | checkout | auth)/…/page.tsx` |
| An admin page                               | `src/app/admin/(console)/…/page.tsx`                   |
| UI for one domain (e.g. a yacht card)       | `src/features/user/yachts/components/`                 |
| Admin UI for one domain                     | `src/features/admin/fleet/components/`                 |
| A function calling a customer endpoint      | `src/services/user/<domain>.service.ts`                |
| A function calling an admin endpoint        | `src/services/admin/<domain>.service.ts`               |
| Response/request schemas for one domain     | the feature's `types/` (or next to its service)        |
| A generic primitive (button, input, dialog) | `src/components/ui/`                                   |
| A generic composite used by both areas      | `src/components/shared/`                               |
| Customer-only chrome / admin-only chrome    | `src/components/user/` / `src/components/admin/`       |
| A Zod schema used by several features       | `src/validation/`                                      |
| A tiny general-purpose helper               | `src/lib/`                                             |
| A new environment variable                  | `.env.example` + `src/config/env.ts`                   |
| A link target                               | `src/constants/routes.ts` (`userRoutes`/`adminRoutes`) |
| A test                                      | `tests/unit`, `tests/integration` or `tests/e2e`       |

Keep route files thin: they await params, call a service, and render feature components.

## Placeholder pages

Every route renders `RoutePlaceholder` ("Starter page — not yet implemented"). Replace it when you
build the page. When no route uses it any more, delete
`src/components/shared/route-placeholder.tsx`.
